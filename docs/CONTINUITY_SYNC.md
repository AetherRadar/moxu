# 生成前连续性检查

2026-09-24。实现范围为 AI 写章的开始、回答后写作、按反馈重写及流式重写入口。不是所有规划/编辑接口的统一版本控制。

## 执行流程

1. 前端等待本标签页已发起的草稿保存完成。同章保存串行执行，保存失败时阻止继续。无法等待其他标签页尚未发送的编辑。
2. 后端扫描目标章节之前的正文与标题哈希，并核对设定、事实、时间线、人物状态及摘要版本。再检查全书因果报告版本；两项均通过且无待核对项目时才进入原生成流程。
3. 多个改动章节合并为一个持久化同步任务，确认后仅重新抽取这些章节。已成功归档且正文、标题哈希匹配的旧记录可以建立初始检查点；缺少可靠记录的章节需要首次同步。
4. 对比新旧 facts、timeline、character states 的规范化结构，忽略证据文本、置信度及记录时间等元数据差异。此处不是 LLM 语义等价判断，改写同义事实仍可能进入核对。
5. 针对变化条目的实体字段构建该批次共用的实体到章节反向索引，扫描全书已有正文得到后文候选。无实体线索时保守扩大范围。调用既有启发式冲突检查，并展示旧/新数据供作者核对。
6. 仅保存变动章节派生信息；用户卡片不由同步自动覆盖。旧的后续记忆包失效但不逐章重新生成；目标章沿原写作流程构建当前记忆。
7. 派生信息同步完毕后，未建立或过期的因果报告进入全书因果核查。报告完整且待处理项已逐项处理后，无事实变化则自动继续；有事实变化仍须确认后继续。确认只表示作者已核对，不表示系统证明无剧情矛盾。

## 全书因果核查

### 索引与传播

- 首次经作者确认后，为全书已有非空正文建立事件索引，包括目标章节之后已经存在的章节。不会调用模型改写正文。
- 每章按不超过 8000 个 UTF-16 字符切段，优先段落边界，不截断代理对。每段提取事件、前提、结果、带原文证据的别名，以及无法确认的部分。
- 追踪生死、位置、物品归属、知识、能力、关系、承诺、资源等结构化状态。按章节和原文位置重放事件，建立 `requires` 和 `state_transition` 边。普通移动、转交等状态变化不直接判为冲突。
- 所有证据绑定正文 SHA-256 和字符位置；模型输出必须通过严格 JSON/schema 与原文子串校验。重复引文不能可靠定位时标为不确定。
- 倒叙、梦境、假设和时间不明场景保留在事件图中，但不覆盖主叙事状态；身份歧义、低置信度及推断前提不当作已证实事实。此类缺口要求作者核对。
- 新旧图合并依赖遍历覆盖删除事件和多跳传播。别名变化导致的节点语义变化也会触发影响计算，不限于正文直接修改的章节。

### 增量与成本

- 纯本地正文哈希检查不调用模型。索引缓存以章节、全文哈希、分段范围、模型配置指纹及算法版本为键，未改章节不重复提取；改动一章目前重提该章全部分段。
- 复核缓存绑定疑点、两处原文窗口和两章之间的正文版本。无关区间改动复用结果；中间章节改动使相关复核失效。
- 每次重放结构化事件图，不重新把整本书交给模型。模型复核只针对疑点，使用两处各约 4000 字符加证据长度的原文窗口；找不到前提不等同于前提为假。
- 全书共用一个持久化报告，切换生成目标不重建另一套索引或绕过旧问题。
- 预算为同一任务的累计 Token / 累计运行时间，默认 200000 Token、30 分钟，Token 设为 0 才表示不限。服务端在调用前预留保守预算，实际用量未知时保留估计计费。取消在调用边界生效，当前调用仍可能完成。
- 进程中断、预算暂停、取消或模型失败后可恢复；已经成功提取/复核的缓存继续使用。任务不会在进程重启后自动付费续跑。

### 报告与放行

- 问题分为“有证据的疑似冲突”“已有解释”“证据不足”。`complete` 只代表本轮流程完成，不表示逻辑上证明作品自洽。
- 报告显示原文章节、引文、字符区间、最多 16 个上游关联事件、索引进度、疑点复核进度、缓存命中和预算用量。完整节点/边可通过 graph 接口读取。
- 已解释项自动通过；其余项目由作者逐项接受风险，或填写依据标记为误报。可重新打开已处理项。不会批量静默忽略未处理问题。
- 任何正文新增、修改、删除或模型指纹改变，旧版本确认均失效，需要重新检查；未改动索引仍可复用。
- 未完成、过期、读盘异常、证据未处理时，后端生成入口拒绝继续，不能靠关闭弹窗或旧“已核对”按钮绕过。
- 正文读取采用严格模式，不把 I/O 错误当作空书；重复归一化章节目录会阻止检查，需先消除歧义。

### 接口与存储

以下接口前缀为 `/projects/{projectId}/session/continuity/{chapter}/causal`：

- `GET` 前缀本身：当前报告，不触发模型调用。
- `POST /run`：`revision`、`max_tokens`、`max_minutes`，开始或恢复任务。
- `POST /cancel`：停止全书任务后续调用。
- `POST /decisions`：`revision`、`finding_id`、`resolution`、`note`；resolution 为 `accepted_risk`、`false_positive` 或 `reopen`。
- `GET /graph`：当前版本的事件、依赖边、疑点与覆盖缺口。

`analysis/causal/reports/V0C0.json` 保存项目级报告；`extraction/`、`verification/`、`graph/` 存放哈希缓存。用量沿用 `analysis` 的任务账本。报告、索引包含正文引文，应与作品文件同等保护。当前尚未自动回收旧版本缓存。

## 恢复与异常

- `analysis/applied/<章节>.json` 保存已入库正文与标题哈希、规范化事实快照。预览缓存不视为已入库。
- `analysis/continuity/<目标章节>.json` 保存范围、分析 job_id、旧/新变化与关联章节。保留项目级待核对状态，换一个生成章节不能绕过未完成核对。
- 模型失败、预算暂停、部分保存或进程中断后可恢复。原有分析任务用量账本同时记录同步调用；保存阶段沿用相同 token 预算。取消在模型调用边界生效。
- 清空/删除已建立检查点的章节会阻止生成。作者明确点击清理后移除该章旧事实、时间线、人物状态及摘要，失效卷摘要，然后核对后续影响。不改写或删除正文。
- 同步期间正文变化会拒绝原检查结果。多文件保存不是事务，不支持多后端共同写同一作品。

## 限制

- 因果图是“模型提取的事件与状态依赖图”，不是自然语言的完备逻辑证明。代词、省略、隐含因果、不可靠叙述、复杂时间线或提取遗漏仍可能造成漏报/误报，不自动修复后文。
- 复核读取有界证据窗口，不是每个疑点都让模型重新通读全书；窗口之外的解释可能需要作者补充依据。倒叙等当前按覆盖缺口处理，尚未构建统一世界时间轴。
- 本地结构化状态重放仍扫描全图；没有实现检查点收敛提前终止。影响传播按图遍历而非“最早改章到末章全部付费重跑”。
- 模型配置/算法版本改变会失效因果报告与相应提取缓存；不会因此把用户卡片自动覆盖。
- 正文哈希检查需要读取前文；复杂度仍随作品长度增长，节省的是模型调用与无关记忆重建。
- 仅已有入库检查点才能可靠识别被删除章；缺少历史记录的旧项目不能凭空还原已删除内容的来源。
- 本标签页保存屏障不能代替跨标签页/跨进程并发版本锁；生成请求之后的外部编辑也不能撤回已发出的模型请求。
