# 交互与生成性能改进

2026-09-21

本轮围绕书库、创作工作台、流式正文、总纲与卷纲候选、章节拆分和章节分析进行优化。模型选择、提示词、上下文预算、采样参数、数字保护和修改确认流程保持原有配置。

## 交互

- 侧栏展开、面板切换和助手模式切换增加短过渡；遵循系统的减少动态效果设置。
- 左侧导航边界支持鼠标、触摸指针和键盘调宽，宽度会保存到本机。方向键调整 10px，Shift 调整 40px，Home/End 到边界，Enter 或双击恢复默认。
- 写作搭档改为右下角彩色笔形入口，默认收起。点击打开 560px 浮窗，可展开至 800px；手机端按屏幕宽度适配，开关均不挤压正文。浮窗支持 Escape 或关闭按钮收起，点击工作区及切换规划时保持打开，并保留未发送的要求；生成期间笔形入口显示状态标记。
- 拖动标题栏可移动浮窗，收起时也可拖动笔形入口；支持鼠标、触屏和方向键，位置保存在本机。拖动与点击分开处理，调整窗口或屏幕尺寸时自动限制到可见范围内。
- 规划模式在浮窗中提供总纲、卷纲和章节续写规划入口；具体工具在独立弹窗中打开。大纲提示词注入后重新展开助手。新建章节与生成前确认继续使用各自弹窗。
- 把笔拖到正文、大纲、人物设定、故事记忆或模型设置，落点高亮，松手打开对应工具；具体总纲、卷纲和章节纲落点直接打开相应弹窗。空白处只移动笔，取消拖动不触发动作。拖放不发送生成或写入请求。
- 续写探索和模型配置弹窗放到页面顶层，保持键盘焦点并适配窄屏，避免被助手浮窗裁切。
- 正文和助手消息在阅读末尾时跟随更新，向上阅读时暂停跟随，可点击返回最新内容。
- 起草、修改、润色、大纲候选、拆章和批量分析显示活动状态及真实耗时。活动条不表示完成百分比。
- 生成期间禁用重复提交，仍可编辑下一条要求。
- 三类生成弹窗在页面顶层显示，避免被侧栏遮挡；补全键盘焦点循环、关闭后焦点恢复和窄屏布局。

## 提速范围

1. **完整正文立即显示。** HTTP 已返回完整正文时直接进入编辑器，去掉原先额外的逐字回放。真正的 WebSocket 流仍逐批显示；切换项目时取消遗留的刷新帧。
2. **模型客户端按配置复用。** 配置未变时复用提供商实例；模型、密钥等配置变化后重建，删除配置后清理旧实例。网关注册表访问同步化，网络调用不持有注册表锁。现有代理兼容策略保留，不能据此宣称所有提供商都复用了 TCP 连接。
3. **收到流结束标记及时返回。** OpenAI 兼容接口的同步聚合路径收到 `[DONE]` 就停止读取，不再等待代理关闭 HTTP 响应。保留结束原因和 usage；缺少终止信息的半截响应标记为 `incomplete`，润色校验会拒绝它。
4. **独立分析步骤受控并行。** 手动及批量章节分析中的章节摘要和事实提取共享进程级并发额度，默认 2；汇总、校验及后续写入仍按原流程进行。自动归档路径保持原逻辑。任一步骤抛出异常时取消另一任务，退出时释放额度。
5. **页面按需加载。** 书库入口不再提前下载整个写作工作台。

启动前导出 `MOXU_ANALYSIS_CONCURRENCY=1` 可将分析恢复为串行，适合只允许一个并发请求的模型服务。允许范围为 1–4，也可使用 Spring 配置 `moxu.generation.analysis-concurrency`。并行改变等待顺序，不减少模型请求、提示词或输出预算。

悬浮助手后续验收覆盖 1440px、1024px、390px、320px，以及 320×568 的英文短屏：开关前后正文位置与宽度相同；输入保留、放大、Escape、规划弹窗、生成前确认、新建章节及专注模式均通过。新增鼠标和触屏落点验收覆盖正文、大纲、三类规划弹窗、设定、记忆及模型配置，检查保持打开、焦点、取消拖动和零写入。浏览器测试拦截实际写入和生成请求，未修改作品内容。脚本与截图保存在 `work/floating-assistant-*` 和 `work/assistant-context-*`。

运行验证：

```bash

```

建议使用 JDK 21。本机默认 JDK 25 与当前 Mockito/Byte Buddy 版本不兼容；验证使用已安装的 JDK 21，没有为此更换依赖。原有三项单次请求测试仍假设 `stream=false`，改动前也失败；已调整为当前实现的单次流式传输协议，仍检查请求次数、token 上限和截断拒绝行为。

构建仍提示 Browserslist 数据较旧，以及工作台分块超过 500KB。书库分包已降低首屏负担，工作台自身还有继续拆分的空间。

本机测试数据、截图和浏览器验证脚本位于 `work/interaction-*`；测试后端使用独立的 `work/interaction-qa-data`，没有写入用户小说。最初的性能验收构建输出位于 `.moxu-runtime/interaction-*`；下述 CRUD 修复使用 Maven 默认的 `backend-java/target` 构建，再更新预览 jar。本轮开始前的源码快照保存在 `work/before-interaction-performance-20260921.tar.gz`，仅用于本机恢复，不应提交或分享。

## 新建章节与删除作品卡住修复

- 新建空章节原先在持久化后同步触发审阅和写作上下文准备，其中包含模型请求。现在空白正文不触发这些步骤，开始生成时仍按原流程准备上下文；有正文的保存仍保留原有审阅流程。
- 章节写入成功后立即切换到新章，更新本地章节编号、标题和正文缓存。列表与大纲在后台刷新，不再决定创建弹窗何时关闭；后续刷新失败不会误报创建失败。写入失败保留弹窗及输入。
- 顶部作品菜单和书库共用 `projects-list` 缓存；创建、改名和删除成功后直接更新缓存，避免必须刷新页面才能看到结果。删除期间显示忙碌状态并防止重复提交，失败显示可重试提示。
- 删除当前作品直接返回 `/library`，避免首页自动跳转等待列表请求，或在删掉最后一本时自动创建默认作品。

Java 21 下 22 项相关后端回归通过，新增测试实际写入临时目录并验证空章节不调用 AI、有正文时仍刷新辅助资料。`work/crud-ui-regression.mjs` 使用独立的 3002/8082 服务和临时数据目录进行真实 CRUD；覆盖列表刷新被阻塞时创建成功、失败输入保留与重试、防重复提交、删除失败提示、书库缓存同步，以及删除最后一本后保持空书库。没有对用户作品执行测试写入。截图和结果保存在 `work/crud-*`。

## 大纲实时同步与三类卡片提取

- 左侧与正文区的大纲编辑器共用按作品、总纲、卷和章节区分的草稿状态，输入及 AI 候选应用立即双向显示。停止输入 700ms 后自动保存，每个目标串行写入，慢响应不会覆盖后续输入。切换面板不会取消待保存任务，尚未落库的草稿保存在本机，可在刷新后恢复。失败自动重试两次并保留手动重试入口；大纲不再使用手动保存按钮。
- 卡片库的 AI 入口与大纲的“提取卡片”共用筛选工作台。材料可包含当前大纲草稿、章节摘要、已保存的当前正文和作者补充。材料不做静默截断，超过 12 万字符时要求缩减选择范围。
- 角色、世界设定、文风分别调用提取接口，三个请求并发执行；后端全局最多允许三个提取请求进入模型。单模块失败可独立重试，不清空其他结果。使用已有 extractor 模型配置，每模块最多 6000 输出 token；未完成或格式错误的结果显示错误，不伪装成提取为空。
- 候选支持搜索、勾选、修改描述与附加字段，并显示来源与原文依据。依据在后端核对，不匹配时明确标记；同名、待确认或依据未核实的候选默认不勾选。文风作为现有单一文风卡的候选更新，入库前保留原始文风元数据。
- 只有作者勾选并点击入库才写入卡片。入库前再次核对同名内容；部分失败保留结果，重试跳过已成功项。卡片库自动刷新。角色、设定、文风分别使用青绿、金色和玫红色标识，弹窗在桌面使用双列，在窄屏使用单列。

回归覆盖共享草稿、请求顺序、失败恢复、三模块并发、结构化结果与依据校验。浏览器脚本 `work/outline-cards-ui-test.mjs` 在独立临时作品中运行真实大纲读写和卡片入库，AI 输出使用受控响应；覆盖双向同步、应用生成候选、切换保存目标、单类重试、作者修改、同名默认不选、部分入库重试，以及 1440px / 390px / 320px 布局。未调用用户线上模型评估提取质量，也未修改用户作品。截图为 `work/card-studio-*` 与 `work/card-library-result.png`。

### 提取接口版本不一致修复

本机同时存在 3000/8080 与 3001/8081 两组服务。前一组后端仍运行旧 jar，缺少新提取接口；新前端访问时三个模块全部返回 `404 Resource not found`。已重新构建并更新两组服务，分别通过前端代理核对三类 POST 路由。

- 新增只读能力查询 `GET /projects/{projectId}/cards/extract-candidates`。提取前确认三类接口可用；检查失败不进入候选阶段，输入和选材仍可编辑。
- 浏览器在旧后端下实际验证了中文服务提示和输入保留。前端构建通过；8 项提取回归覆盖 MVC 路由、并发、结构与依据核验，以及模型限流、断连、超时的安全错误提示。
- 使用已配置模型的真实调用另发现上游断连及 `gateway_concurrency_limit`（账户并发限额），与本地 404 是不同问题。错误现在明确指出上游原因，不回显模型服务的原始响应或敏感字段。
- 最终真实页面测试返回角色 1 张、世界设定 2 张、文风 1 张。世界设定首次遇到限流，独立重试后成功；期间角色、文风候选和作者手动修改均保留。3001 入口的单模块真实请求也成功返回文风候选。模型给出的依据未通过逐字核验，界面正确标记需人工核对、默认不选中，未放宽核验规则。端到端链路已跑通，但不能据此宣称上游服务稳定或生成质量已完成评估。
- 测试只提交临时编写的设定材料，没有将测试候选入库或修改小说内容。

### 模型连接与重试优化（2026-09-22）

新一轮日志显示多个模型请求约 30 秒后出现 EOF，原先仅隔 1 秒、2 秒的重试随后触发账户并发限流。连接中断不代表上游生成已经取消，快速重发可能叠加仍在运行的任务。

- 同一 Java 客户端、配置和小型测试请求，强制 HTTP/1.1 在约 30.6 秒时断开，HTTP/2 在约 3.7 秒返回。curl 的 HTTP/1.1 请求也曾成功，说明问题与当前网络及网关的连接兼容性有关，不能将这一次时间差当作普遍提速幅度。
- OpenAI 兼容客户端改为通过 ALPN 优先协商 HTTP/2；不支持的服务器仍使用 HTTP/1.1。移除强制关闭连接的请求头，保留连接池，关闭隐藏的连接失败重发，由网关协调重试。润色的单次请求约束和截断检查保留。
- 普通同步生成按提供商共享冷却时间。EOF、读超时默认至少等待 15 秒、30 秒后再试；限流默认等待 10 秒、20 秒，并尊重更长的 `Retry-After`（秒数或 HTTP 日期）。冷却后错开请求启动时间，避免多个模块同时再次冲击服务。最终失败也保留冷却，立即手动重试不会绕过等待。
- 400、401、403、404 等不可通过等待恢复的错误不再反复生成。兼容接口仍可在首次 404 时尝试既有备用路径。错误对象只保留 HTTP 状态、等待时间及已识别的限流类型，不保存上游原始错误正文。
- 模型、完整材料、温度、输出预算和结果校验未降低。回归实际比对重试前后的请求体，验证等待时间、断连恢复、永久错误不重发、不同提供商隔离、队列错峰和取消。287 项后端全量测试通过；随后补充 HTTP/2 reset/shutdown 分类，58 项相关回归再次通过。

真实测试先在 8081 服务返回三类候选（约 136 秒），随后在当前 3000 前端代理入口通过最终版本再次验证：角色 1 张、世界设定 2 张、文风 1 张，总计约 103 秒。最终一轮仍遭遇 HTTP/2 `StreamResetException` 和一次 429，但按冷却策略自动恢复，未要求作者手动重试；不能把这两轮耗时差当作稳定的性能提升幅度。两次测试结果均未入库，未放宽原文依据核验。

已更新当前 8080 后端及既有 8081 预览后端；3000 前端进程保持运行，以保留现有弹窗状态。最终运行信息在 `work/original-server-state.json`，实际入口测试记录在 `work/card-transport-deployed-live.log`。

冷却按后端进程及配置的提供商区分，不是跨软件共享的账户限额管理。它能减少本软件的重试叠加，不能保证上游服务可用或消除模型生成耗时。
