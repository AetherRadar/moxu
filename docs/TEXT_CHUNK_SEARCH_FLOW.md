# 文本分块检索 - 流程图说明

用流程图说明「当前实现」和「推荐方案」的区别。

---

## 零、原理入门（先搞懂这几件事）

### 我们要解决什么问题？

写作时，系统需要从**已有章节**里找出「和当前要写的内容最相关」的段落，给 AI 当参考。  
比如你要写「张三用剑法击败李四」，系统就要在 100 章里找出提到「张三」「剑法」「李四」的段落。

---

### 核心概念 1：分词（tokenize）

电脑不能直接理解「张三 剑法」这句话，需要先拆成**词**：

- 「张三 剑法」→ `[张三, 剑法]`
- 「他修炼了三年」→ `[修炼, 三年]`（「他」「了」太短会被过滤）

分词是**有成本的**：要对整段文字跑正则、建集合，文字越长越慢。

---

### 核心概念 2：怎么判断「相关」？

简单做法：看**重叠**。

- 你搜的词：`[张三, 剑法]`
- 某段落 A 的词：`[张三, 剑法, 修炼, 三年]` → 重叠 2 个，相关
- 某段落 B 的词：`[李四, 刀法, 逃跑]` → 重叠 0 个，不相关

重叠越多，分数越高，就越相关。

---

### 核心概念 3：为什么当前做法会慢？

**类比：在 100 本书里找「提到张三和剑法的段落」**

**笨办法（当前实现）**：  
每次有人来问，你就：
1. 打开第 1 本书，一页一页翻，把每段拆成词，看有没有「张三」「剑法」
2. 打开第 2 本书，重复
3. … 一直到第 100 本

问一次，就要翻完 100 本书。问 10 次，就翻 1000 遍。

**聪明办法（索引）**：  
事先做一本**目录**：
- 「张三」→ 第 3 本书第 5 段、第 7 本书第 2 段、……
- 「剑法」→ 第 3 本书第 5 段、第 12 本书第 8 段、……

有人来问时，直接查目录：两个词都出现的段落，就是答案。不用再翻书。

---

### 核心概念 4：倒排表是什么？

**正排**：按「段落」看，每段里有哪些词  
- 段落 1 → [张三, 剑法, 修炼]  
- 段落 2 → [李四, 刀法]  
- 段落 3 → [张三, 剑法, 李四]  

**倒排**：按「词」看，每个词出现在哪些段落  
- 张三 → [段落 1, 段落 3]  
- 剑法 → [段落 1, 段落 3]  
- 李四 → [段落 2, 段落 3]  

查「张三 + 剑法」时：  
张三在 1、3，剑法在 1、3 → 两个都有的只有 1、3 → 段落 1 和 3 最相关。

倒排表就是把「正排」反过来的一个**预先算好的表**，查的时候直接查表，不用再打开每个段落重新分词。

---

### 小结：原理一句话

- **当前**：每次问，都重新翻所有书、拆所有段、算所有分 → 慢  
- **推荐**：事先做好「词 → 段落」的目录（倒排表），问的时候只查目录 → 快  

---

## 一、当前实现：每次查询都做什么？

```
用户发起一次搜索（例如：搜「张三 剑法」）
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  searchTextChunks(projectId, "张三 剑法", limit=8)       │
└─────────────────────────────────────────────────────────┘
         │
         ▼
    ┌────────────┐
    │ 第 1 章    │
    └────────────┘
         │
         ├──► 读 final.md（读磁盘）
         ├──► splitIntoChunks()（把整章切成很多小段）
         │
         │    对每个小段 chunk：
         │         ├──► tokenize("张三 剑法")     ← query 重复分词！
         │         ├──► tokenize(chunk)           ← 每个 chunk 都分词
         │         └──► 算 overlap，算 score
         │
         ▼
    ┌────────────┐
    │ 第 2 章    │
    └────────────┘
         │
         ├──► 读 final.md
         ├──► splitIntoChunks()
         │    对每个 chunk：tokenize × 2 + 算分
         ▼
    ┌────────────┐
    │ 第 3 章    │  … 重复 …
    └────────────┘
         │
         ▼
       … 第 N 章 …
         │
         ▼
┌─────────────────────────────────────┐
│ 把所有 chunk 按分数排序，取前 8 个   │
└─────────────────────────────────────┘
         │
         ▼
      返回结果
```

**一句话**：每次搜索 = 遍历所有章节 → 每章读文件、切分、对每个小段分词算分 → 再排序。

---

## 二、为什么慢？用数字感受一下

假设：**100 章**，每章 **50 个小段**，一共 **5000 个小段**。

| 操作 | 做了多少次？ |
|------|--------------|
| 读 final.md | 100 次（每章 1 次） |
| 切分章节 | 100 次 |
| tokenize(query) | 5000 次（每个小段都重新对 query 分词） |
| tokenize(chunk) | 5000 次（每个小段都分词） |
| 算分 | 5000 次 |

**同一次搜索里**：query 被分了 5000 次、每个 chunk 也被分了 5000 次（虽然很多 chunk 根本不会命中）。

章节越多，这些数字线性放大，所以会越来越慢。

## 三、推荐方案：把「重活」提前做完

### 3.1 建索引（只在 rebuild 时做一次）

```
用户点击「重建索引」或首次使用
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  rebuildTextChunkIndex(projectId)                        │
│  （遍历所有章节，一次性把该干的活全干完）                  │
└─────────────────────────────────────────────────────────┘
         │
         ▼
    遍历每一章
         │
         ├──► 读 final.md
         ├──► splitIntoChunks()
         │
         │    对每个 chunk：
         │         ├──► 生成 chunkId（如 chunk:V1C01:3）
         │         ├──► tokenize(chunk) 一次
         │         ├──► 把 chunk 信息存进 chunks.json
         │         └──► 把每个 term → chunkId 写进倒排表
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  落盘 3 个文件：                                          │
│  • meta.json        （版本、统计）                        │
│  • chunks.json      （每个 chunk 的 id、文本、长度等）    │
│  • inverted_index.json  （词 → 出现在哪些 chunk 里）      │
└─────────────────────────────────────────────────────────┘
```

**一句话**：rebuild 时把所有章节切好、分好词、建好索引，并保存到磁盘。

---

### 3.2 查询时（只做轻量操作）

```
用户发起一次搜索（例如：搜「张三 剑法」）
         │
         ▼
┌─────────────────────────────────────────────────────────┐
│  searchTextChunks(projectId, "张三 剑法", limit=8)       │
└─────────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────┐
│ 1. 读入索引文件（chunks + 倒排表）   │  ← 只读一次
└─────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────┐
│ 2. tokenize("张三 剑法") → [张三,剑法] │  ← query 只分词 1 次
└─────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────┐
│ 3. 查倒排表：                         │
│    "张三" → [chunk:A, chunk:B, ...]   │
│    "剑法" → [chunk:A, chunk:C, ...]   │
│    对每个命中的 chunk 做 overlap 计数  │
└─────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────┐
│ 4. 按 score 取 top 8，从 chunks 里   │
│    取出对应文本，返回                 │
└─────────────────────────────────────┘
         │
         ▼
      返回结果
```

**一句话**：查询时只对 query 分一次词，用倒排表快速找到相关 chunk，再取 topK，不再遍历所有章节和 chunk。

## 五、倒排表是什么？（通俗版）

**正着想**：每个 chunk 里有哪些词？
- chunk:V1C01:0 → [张三, 剑法, 修炼, ...]
- chunk:V1C01:1 → [李四, 刀法, ...]

**倒过来想**：每个词出现在哪些 chunk 里？
- "张三" → [chunk:V1C01:0, chunk:V1C02:5, ...]
- "剑法" → [chunk:V1C01:0, chunk:V1C03:2, ...]

查询「张三 剑法」时：
1. 查 "张三" 出现在哪些 chunk
2. 查 "剑法" 出现在哪些 chunk
3. 两个列表里都出现的 chunk，就是同时包含这两个词的，overlap 高，分数高

这样就不用再打开每个 chunk 的原文、重新分词，只需要查表、计数。
