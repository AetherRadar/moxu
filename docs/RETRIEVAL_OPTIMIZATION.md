# 检索算法优化

2026-09-24。本轮范围是 Java 本地检索、评分与正文索引，不更换模型、不增加付费模型调用、不改写正文或卡片。

## 1. 评分统计复用

`TextSearchUtils.Scorer` 为单次检索保存查询词权重、文本词频和文档长度。同一个文本的统计在 IDF 构建与混合评分之间复用，不再为 overlap、BM25 各自重复分词查询和候选文本。

- 继续使用既有 Jieba 分词、项目专名词典、词项权重、短语加分和 BM25/overlap 混合公式。
- 缓存只存活于一次检索，不跨作品、不跨词典版本，也不把旧文本统计用到新正文。
- 相同文本的分词统计可以复用；IDF 仍按实际文档数量计算，重复文档仍计入文档频率。
- 单独调用旧的 `calculateHybridScore` API 也会共用该次评分的统计，不要求调用方全部迁移。

## 2. 候选召回和事实去重

- 角色卡、世界卡、事实不再按存储顺序只取前 50 条。先对完整候选集合评分，再按 topK 返回；正文片段保留既有的返回候选上限。
- 事实去重从两两相似度比较改为文本键集合，避免反复分词与成对比较。只规范化首尾及重复空白，不删除否定词、数字、标点或附加条件。
- 不再把高词项重合度、子串包含关系当成事实等价。例如“拥有钥匙”“不拥有钥匙”“拥有钥匙但不能使用”都保留。
- 仍保留既有低信息量事实质量评分。去重变得保守，可能保留更多近似事实；这不是新的语义去重模型。

取消前 50 条截断会扩大可检索范围，也可能改变排序。基准中的“评分一致”只针对相同语料、相同词典、相同公式，不代表扩大候选集后最终结果不变。

## 3. 正文增量索引

每次正文检索取得当前 `final.md` 快照并核对 SHA-256，不仅比较文件时间或大小。编辑器外部的同长度改字、恢复修改时间，也会使对应章节失效。

1. 首次检索或旧格式索引自动重建，不需要作者手动操作。
2. 正文未变、分词/分段版本和专名词典未变时复用索引，不重新分词，也不重写索引文件。
3. 少量改稿时，只对这些章节重新分段和分词；其余章节复用已有片段、词项和长度。
4. 新增、删除、清空章节会更新倒排表、文档数量和平均文档长度，不保留已删除正文的命中。
5. 词典或算法版本变化需要全量重建；明确调用原有 rebuild 接口也会强制全量重建。
6. 进程重启后可以复用磁盘索引，再做增量更新。

索引持久化沿用 `text_chunk_index/meta.json`、`chunks.json` 和 `inverted_index.json`。元数据增加：

- `format_version`、`source_hashes`
- `refreshed_chapters`、`reused_chapters`、`removed_chapters`
- `chunks_hash`、`inverted_hash`

片段与倒排表先写，带校验和的元数据最后写。读到损坏或混合版本时从当前正文重新构建。同一后端实例内按作品串行刷新，不让并发请求互相覆盖临时文件；不同作品不共用刷新锁。

读盘失败不会退回旧索引返回过期正文。索引保存失败时，本次可以使用已经从当前正文建立的内存结果，后续请求会重新尝试落盘。正常正文检索仍只索引 `final.md`，不把旧 `draft_*.md` 或其他目录当成已写正文。

## 4. 片段和过滤

- 长段落不再突破 420 个 UTF-16 字符的片段上限。优先句末、换行分割，硬切时不拆开 Unicode 代理对；不截掉剩余正文。
- 短段落仍按原规则组合。新增分段版本会使旧索引迁移，片段编号可能变化。
- 显式非空但无有效章节的包含范围返回空结果，不退化为全书搜索。原有 null/空列表仍表示不限定范围。
- 累加倒排命中时提前排除范围外章节，减少中间候选占用。
- 正文 topK 继续使用有界堆，同分按卷号、章号、片段号排序，结果不再依赖哈希表迭代顺序。

## 5. 验证与局限

新增测试覆盖中英文评分等价、词典隔离、201 条事实召回、超过 50 张卡片、否定/数量差异、200 章单章更新、外部改稿、删除、重启复用、索引损坏、并发查询、空前文范围、Unicode 长段落和稳定 topK。

一次本地合成基准：200 条文本，三轮中位数，旧评分过程约 44.5 ms，复用统计后约 16.6 ms，耗时比约 0.374。相同语料的评分校验通过。该数据仅反映本地评分阶段，不包含磁盘读取、模型响应或真实作品质量验收，不能换算为整次生成提速或 Token 降幅。

后续全量回归中的同一基准为 24.3 ms / 8.6 ms，耗时比约 0.352，说明绝对耗时会随预热和运行负载变化。2026-09-24 验证结果：后端 413 项、前端 72 项通过，无失败或跳过；差异空白检查通过。本轮未修改前端代码，未推送或重启现有服务。

复现命令（Java 21）：

```powershell
mvn -f backend-java/pom.xml "-Dtest=RetrievalPerformanceTest,IncrementalTextIndexTest" test
```

基准输出 `RETRIEVAL_BENCHMARK`；只对结果正确性设断言，不用机器相关耗时作为测试通过条件。

仍有的成本与边界：

- 为正确识别外部修改，正文哈希仍读取当前全书正文；不是 O(1) 新鲜度检查。
- 少量章节变化后，全局倒排表汇总和索引序列化仍有全书规模成本，节省的是未改章节的分词/分段。
- 完整候选召回需要读取全部相关卡片/事实，单次评分统计占用随候选集增长；没有跨请求持久化卡片索引。
- 分段边界上的跨片段长短语仍可能影响召回；尚未引入跨片段匹配或语义向量检索。
- 不提供多后端共享目录的事务或跨章节原子快照；检索进行中的外部编辑由下一次检查发现。
- 没有使用用户作品或真实付费模型测量生成质量，也未宣称达到全书分析 50% Token 降本目标。
